# 订单通 · 智能售后助手

GitHub：[Lxiwen-xi/dingdantong-order-agent](https://github.com/Lxiwen-xi/dingdantong-order-agent)

一个可以本地运行的订单售后 Agent 项目。通过管理页面新增、修改或 CSV 导入订单，再用自然语言查询订单、核对自定义演示规则、试算商品退款金额，并展示每次工具调用。

## 快速运行

这台电脑已安装独立环境，直接双击 `启动订单通.cmd` 或 `start.cmd`，网页地址为 http://127.0.0.1:8602 。启动器优先使用本项目 `.venv`，其次使用父目录已有的 `.venv`。

在 PyCharm 中打开本目录，解释器选择本项目 `.venv/Scripts/python.exe`（如未安装，可选 `D:/AI-Agent-Projects/.venv/Scripts/python.exe`），运行 `run.py`。不要用普通 Python 方式直接运行 `app.py`。

本项目也包含 `.run/订单通.run.xml` 共享运行配置，右上角选“订单通”后点击绿色运行按钮即可。首次启动成功会打开网页；已有服务时直接打开页面并正常退出启动检查。

下载到新电脑后，安装 Python 3.11 及以上，运行 `setup.cmd` 安装独立环境，再运行 `start.cmd`。也可手动执行：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe run.py
```

首次启动自动生成 `data/orders.db`，无需手动建表。默认离线演示不需要密钥。

本机完整验证环境的版本另存于 `requirements.lock.txt`；需要复现相同依赖时可改为安装该文件。

## DeepSeek 配置

在 PyCharm 中运行 `设置DeepSeek密钥.py`，在遮挡输入窗口填写自己的密钥并点击“加密保存”。程序使用 Windows 当前用户 DPAPI 加密，密文保存在 `%LOCALAPPDATA%/OrderAgent/secrets/deepseek-key.dpapi`，不放在项目目录中。保存和解密回读验证通过后，自动清除 `.env` 中的明文密钥；不生成明文备份。

`.env` 仅需保留 `DEEPSEEK_KEY_STORAGE=windows_dpapi`、模型名称与接口地址，`DEEPSEEK_API_KEY` 留空。默认 `DEEPSEEK_MODEL=deepseek-flash`、`DEEPSEEK_BASE_URL=https://api.deepseek.com`。模型和地址支持对应系统环境变量覆盖；加密模式下密钥只从本项目专用密文读取，不回退到明文密钥，也不读取其他项目的密钥。

页面切换至“DeepSeek 智能咨询”，勾选模型调用授权后发送问题。每次提交重新读取配置，程序在后台自动解密。密钥不在页面、导出文件和项目日志中展示。`.env`、密文、数据库和日志均已加入 Git 忽略规则。别人下载源码后需设置自己的密钥；换 Windows 用户或新电脑时也应重新设置。详见 `密钥加密说明.md`。

已有明文配置可执行 `.venv/Scripts/python.exe 设置DeepSeek密钥.py --migrate-env` 迁移。需要无桌面部署时可显式设置 `DEEPSEEK_KEY_STORAGE=environment`，再通过部署平台的环境变量注入密钥；该模式不使用本机 DPAPI。

客户端按 [DeepSeek 官方工具调用示例](https://api-docs.deepseek.com/guides/tool_calls/)使用非思考模式，工具描述通过 `bind_tools` 提供，结果通过 `ToolMessage` 回传。

## 添加自己的订单

左侧“工作区”选择 **订单管理**。管理页面不调用模型，不需要密钥。

1. **订单列表**：按订单号或商品名称筛选，查看来源、状态、金额、签收日期和商品明细。
2. **新增 / 修改**：新增订单时录入一条商品明细；修改已有订单时可更新当前商品、添加其他商品，并更新整笔订单的状态与物流。其他商品明细保留。
3. **CSV 导入**：下载模板 → 填表 → 上传 → 查看校验结果及新增/更新预览 → 确认导入。模板另存为 `data/订单导入模板.csv`。

支持字母、数字、下划线和短横线组成的1～40位订单号与商品编号，也支持数字长订单号。商品类别为数码设备、普通配件、服饰、数字商品；状态为待发货、运输中、已签收。

金额填写 **该商品全部购买件数的优惠后实付合计**，不是单价。签收日期用 `YYYY-MM-DD`，已签收必填且不能晚于当前日期，其余状态留空。

CSV 支持 UTF-8/UTF-8 BOM 或 GB18030 编码，最多1000条明细、2MB。必需表头为：`订单号,商品编号,商品名称,商品类别,数量,实付金额,订单状态,签收日期,物流信息`；`已退数量`为可选列。也支持对应英文表头，见 order_management.py 中 COLUMNS。

同一订单多商品对应多行，订单状态、日期、物流必须一致；同批重复商品明细会拒绝。更新已有订单需勾选“允许更新已存在的订单及商品”，以订单号+商品编号更新；未列出的旧商品保留，省略已退数量时保留原值。每批使用一个事务，发生校验或数据库错误时整批不保存。预览后数据发生变化需重新核对。

保存后立即返回“售后咨询”即可询问新订单。新增或更新会使旧模型上下文失效，下次咨询重新读取数据库；历史回答保留为历史记录。无需重启或训练模型。订单持久保存在 `data/orders.db`，关闭页面、重启服务均不会清空。

## 功能与边界

- `query_order`：通过参数化 SQL 读取只读 SQLite 订单，含商品明细、优惠分摊后的实付金额和物流。
- `lookup_policy`：按类别读取 JSON 规则，返回可追溯规则编号。
- `estimate_refund`：程序核对订单状态、签收时长、商品条件、数量；金额以整数分计算，缺失信息返回 `needs_info`，质量问题转人工审核。
- 多轮咨询保留最近5轮完整消息，包括工具调用与工具结果，避免切断消息配对；切换运行模式或开始新会话时清空上下文。
- 默认最多3轮工具执行，界面支持1至5轮；每轮最多执行6个工具。达到上限后提供一次不绑定工具的模型总结。
- 页面可展开工具名称、参数与结果，导出当前会话 JSON。界面只展示工具记录，不展示模型内部推理。

## 回答核对与条件确认

最终回答会检查常见金额表达、规则编号、订单状态、签收日期与天数，以及“已退款/已提交”等操作表述。退款金额与实付金额分别核对，规则引用还需与当前试算商品类别匹配，签收日期与业务计算日期也分别核对。发现问题时最多让模型修正一次；仍不通过时，按已有工具结果给出答复，不直接展示未经核对的草稿。普通寒暄仍可自然回答。

退款试算前，程序检查是否已查询对应订单及商品规则。数量、原因、拆封/商品完好/吊牌情况，从当前订单和商品范围内的用户明确原话提取，并保留来源。模型参数不能代替用户确认；无法明确识别的表达保持未知。“如果没拆封”等假设、指令或不确定表述不会被当成确定条件。

缺少信息时可以继续聊天补充，也可以在 **核对本次试算信息** 中只补缺项，点击 **确认信息并继续试算**。页面确认由应用提供可信参数，不由模型自行生成。更换订单或商品后不会直接沿用上一件商品的条件；用户更正为已拆封时，按更正后的条件重新核对。

这些校验覆盖项目约定的常见表达，不是对所有自然语言含义的形式化证明。陌生或有歧义的说法会要求确认，最终仍以演示规则与工具结果为依据。

## 失败后的恢复

请求失败时保留当前问题及已执行的工具记录，并显示请求编号。可点击 **重试本次问题**，无需重新输入；配置问题修正后也能重试。余额/额度、密钥、限流、网络、超时、模型配置和本地数据错误分别提示。问题保存在当前浏览器会话，尚未增加长期会话数据库。

模型客户端保留最多1次自动重试。只读工具遇到 SQLite 临时忙/锁定时最多重试1次；参数错误、未知订单和不符合售后条件不按临时网络故障盲目重试。

`logs/events.jsonl` 记录请求编号、事件类型、工具名称、耗时、结果及错误分类，自动轮转。日志不记录密钥、请求头、原问题、订单明细、参数或异常原文；整个 logs 目录已加入 .gitignore。网页中的本次工具记录仍会显示本次查询参数与结果，便于用户自行核对。

## 日期、规则与订单变化

上下文有效性同时检查订单数据版本、当前北京时间日期和规则内容摘要。变化后保留用户原话，清除旧模型结论及工具结果，后续重新查询；处理过程中发生变化会停止发布该次结论，并允许重试。切换到订单管理再返回时，保留当前在线模式、授权选择和会话。

离线模式是显式固定流程，真实执行三个业务工具，但不调用大模型、不能接收任意自然语言咨询。在线模式由模型决定工具与追问。在线行为仍受模型能力影响，界面不把固定流程伪装为模型结果。

内置演示订单使用固定业务日期 **2026-11-03**；自行新增或导入的订单使用 **当前北京时间日期**。修改内置订单后，该订单也会转为本地录入并使用当前日期。页面和工具结果均显示来源与计算日期。离线演示读取当前 A1001 / E01 的实际记录，不再硬编码金额；修改后条件不符时显示工具说明。

自定义规则仅供项目演示，不代表真实商家政策或法律规定。本地录入不等于已与商城核验。没有接电商平台、账号系统、真实退款或售后申请接口。暂不支持一次试算多种商品，需要分别试算。订单数据可长期保存，但聊天没有长期持久化。

## 项目结构

```text
app.py             Streamlit 页面与会话管理
agent.py           LangGraph 模型/工具循环、提示词、上下文裁剪
reliability.py     用户条件来源、答案依据核对与上下文签名
runtime.py         错误分类、请求编号及最小化运行日志
consultation.py    单次咨询执行与失败信息封装
confirmation_ui.py 缺失业务条件的页面确认
tools.py           三个业务工具、输入校验、金额与条件判断
database.py        演示数据建库、参数化只读查询
order_management.py 订单校验、CSV 解析预览、事务写入
management_ui.py   订单列表、录入修改与 CSV 导入页面
config.py          项目内模型配置读取
run.py             PyCharm 直接运行入口
data/policies.json 带编号的自定义演示规则
data/订单导入模板.csv 示例 CSV 模板（页面下载版的日期动态生成）
tests/             业务边界、工作流与页面测试
```

## 技术来源

本项目重新编写订单业务、数据、工具、页面和测试；工作流沿用学习助理中实践的 model → tools → model 思路。该模式的学习来源为 MIT 开源项目 [langchain-ai/react-agent](https://github.com/langchain-ai/react-agent)。未把上游示例的联网搜索业务当作本项目功能。依赖各自遵循其许可证。
